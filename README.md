# LinuxServerAdmin

Linux 서버 관리의 주요 작업 흐름을 정리하고, 저장된 실습 스크립트와 측정 파일을 함께 살펴볼 수 있는 저장소입니다. 저장장치 인식부터 파일시스템과 마운트까지의 연결, 계정·서비스·정기 작업의 확인 방법, 백업본의 생성과 복원 순서를 다룹니다. 예시는 주로 CentOS Stream 9 계열의 실습 환경을 기준으로 합니다.

## 주요 흐름

| 작업 | 먼저 확인할 것 | 변경 후 확인할 것 |
| --- | --- | --- |
| 저장장치 구성 | 대상 디스크·파티션·마운트 상태 | 파일시스템 유형, UUID, 마운트 지점 |
| LVM·RAID·Swap | PV/VG/LV, RAID 구성, 사용 중인 Swap | 볼륨·배열·Swap의 활성 상태와 용량 |
| 시스템 관리 | 패키지·서비스·계정·예약 작업의 현재 상태 | 설정을 적용한 뒤의 상태와 관련 로그 |
| 백업과 복원 | 원본 경로, 백업 위치, 이전 백업본 | 아카이브 목록과 **별도 경로로 복원한 파일** |

일반적인 연결은 `디스크/파티션 → 파일시스템 → 마운트`입니다. LVM을 사용하면 중간에 `PV → VG → LV`가 들어갑니다. RAID를 구성했다면 멤버 장치에서 만든 어레이 위에 파일시스템을 만들거나, 어레이를 PV로 사용하는 등 실제 구성에 맞는 경로를 확인합니다.

## 다루는 범위와 문서

다루는 주제는 디렉터리 구조, 장치 인식·파티션·파일시스템·마운트·점검·용량 확인·LVM·RAID·Swap, 패키지·부팅·사용자/그룹·튜닝, 작업 예약·임시 파일·백업/복구입니다. 아래 문서는 연관된 작업을 저장장치, 시스템 관리, 백업의 세 묶음으로 연결합니다.

| 문서 | 확인할 내용 |
| --- | --- |
| [저장장치 구성 가이드](docs/storage-workflow.md) | 장치 식별 → 파티션/볼륨 → 파일시스템 → 마운트 → 점검. 디스크를 바꾸는 명령은 대상 확인 절차와 구분 |
| [시스템 관리 점검 가이드](docs/system-checks.md) | 패키지·부팅·서비스·사용자/그룹·튜닝·예약 작업·임시 파일의 현재 상태와 설정 위치 |
| [백업·복원 가이드](docs/backup-recovery.md) | 격리된 디렉터리에서 `tar` 전체·증분 백업과 복원, 기존 `backup.sh`와 Borg 스크립트의 전제 조건 |

문서의 구성 예시는 저장소에 실행 기록이 없는 작업까지 완료된 것으로 나타내지 않습니다. 파티션 생성, 포맷, 파일시스템 복구와 계정 변경은 대상에 따라 데이터를 바꾸므로 확인 명령과 변경 명령을 구분해 표시합니다.

## 현재 저장소의 파일

| 위치 | 내용과 해석 |
| --- | --- |
| [`bin/backup.sh`](bin/backup.sh), [`bin/web-backup.sh`](bin/web-backup.sh) | 각각 `/home`을 `/backup`에 `tar`로 보관하거나 원격 Borg 저장소에 파일을 보관하도록 작성된 예제. 경로·권한·원격 저장소·버전을 확인한 뒤 읽을 것 |
| [`bin/work.sh`](bin/work.sh) | 로그 메시지를 남긴 뒤 계속 출력하는 테스트 스크립트. 서비스 Unit 파일은 저장소에 없음 |
| [`bin/coffeetime.sh`](bin/coffeetime.sh), [`bin/coffeetime2.sh`](bin/coffeetime2.sh) | 여러 `pts` 터미널에 내용을 쓰는 코드. 대상 세션과 `/etc/MESS` 파일에 의존하므로 기본 실행 절차에서 제외 |
| [`bin/mem.c`](bin/mem.c), `bin/mem` | 반복적으로 메모리를 할당하는 C 코드와 컴파일된 실행 파일. 종료 조건이나 메모리 해제가 없어 실행 예제로 권하지 않음 |
| [`bin/logs/iperf3_20260420_104605.json`](bin/logs/iperf3_20260420_104605.json), [`bin/logs/iperf3_20260420_104605.json.dat`](bin/logs/iperf3_20260420_104605.json.dat), [`bin/plots/iperf3_20260420_104605.png`](bin/plots/iperf3_20260420_104605.png) | 저장된 `iperf3` 결과·추출한 수치·그래프 한 묶음. JSON에는 TCP·5개 스트림·60초 설정이 기록되어 있지만 반복 측정과 비교 기준은 없으므로 일반적인 성능 수치로 해석하지 않음 |
| [`env/`](env/), 기타 [`bin/`](bin/) | Bash/Vim 설정과 보조 스크립트. 셸 스크립트 11개는 `LinuxEssential`의 파일과 동일하며, 현재 시스템에 바로 적용할 설정으로 취급하지 않음 |

`backup.sh`는 `/backup/backup.log`를 덮어쓰고 오류 시 별도의 검증 없이 끝날 수 있습니다. `web-backup.sh`의 `repo::archive` 구문은 Borg 1.x 형식이므로 설치된 버전을 확인해야 합니다. `bin/disk.sh`, `bin/net_load.sh`, `bin/poweroff.sh` 등도 패키지 설치·부하·삭제·원격 종료를 수행합니다. 스크립트 파일의 존재와 현재 환경에서의 실행 가능성은 구분합니다.

## 읽기 전용 시작점

대상 VM을 확인한 뒤 다음 명령으로 현재 상태를 살핍니다. 출력은 환경에 따라 달라지며, 빈 디스크나 별도 백업 서버가 자동으로 준비되는 것은 아닙니다.

```bash
cat /etc/os-release
lsblk -f
findmnt
df -hT
```

그다음 필요한 작업에 맞춰 위 가이드의 적용 대상과 확인 순서를 읽습니다. 백업 가이드의 로컬 예제는 사용자 권한의 새 임시 디렉터리에서 실행할 수 있으며, 원격 Borg 예제는 별도 환경이 필요합니다.
